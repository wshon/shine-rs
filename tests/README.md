# Test Architecture Documentation

## Test Suite Organization

The test suite is organized into 5 clear categories, eliminating duplicate functionality:

### 1. Basic Functionality Tests (`encoder_basic_functionality.rs`)
**Status**: ✅ All passing
**Purpose**: Verify basic encoder functionality and error handling
**Tests**:
- Basic encoding
- Error handling
- Various input formats

### 2. Live Comparison Tests (`encoder_comparison_live.rs`)
**Status**: ✅ Passing (ignored by default, requires external Shine binary)
**Purpose**: Real-time byte-for-byte comparison against the Shine C reference
**Tests**:
- Default file comparison
- Various bitrates
- Voice files
- Large files

**Note**: Rust output is **byte-for-byte identical** to Shine C. These tests are ignored by default because they require the external `ref/shine/shineenc` binary. Run manually:
```bash
# Run all live comparison tests
cargo test --test encoder_comparison_live -- --ignored

# Run a specific test
cargo test test_default_file_comparison -- --ignored
```

### 3. CI/CD Validation Tests (`encoder_validation_cicd.rs`)
**Status**: ✅ All passing
**Purpose**: Validate against pre-generated reference data (no Shine binary required)
**Tests**:
- Standard configuration validation
- Reference file integrity checks

**Note**: Reference data is generated by the Rust encoder as a regression baseline. Rust output is byte-for-byte identical to Shine C, so these baselines are equivalent to C's reference output.

### 4. Low-Level API Tests (`encoder_low_level_api.rs`)
**Status**: ✅ All passing
**Purpose**: Verify the Shine-compatible low-level API
**Tests**:
- Shine config creation and validation
- Low-level encoding functions
- Memory management
- Error handling

### 5. High-Level API Tests (`encoder_high_level_api.rs`)
**Status**: ✅ All passing
**Purpose**: Verify the Rust-style high-level API
**Tests**:
- Config validation
- Encoder creation
- PCM encoding
- Various configurations
- Stereo modes
- Error conditions
- Full encoding workflow

## Test Commands

### Run all tests
```bash
cargo test
```

### Run a specific test category
```bash
# Basic functionality
cargo test --test encoder_basic_functionality

# Live comparison (ignored by default, run manually)
cargo test --test encoder_comparison_live -- --ignored

# CI/CD validation
cargo test --test encoder_validation_cicd

# Low-level API
cargo test --test encoder_low_level_api

# High-level API
cargo test --test encoder_high_level_api
```

## Numerical Consistency

The Rust encoder is byte-for-byte identical to Shine C across 6 sample-rate/bitrate configurations (22.05/24/32/44.1/48 kHz, 64–192 kbps). The implementation follows Shine C's constants and fixed-point arithmetic conventions to keep the bitstream identical.

## CLI Argument Order

The encode command uses the argument order `-b <bitrate> <input> <output>`.
